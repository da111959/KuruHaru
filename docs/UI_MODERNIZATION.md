## 1. 目标与非目标

### 目标

- 让用户能按“下一步该做什么”而非按内部技术名称理解页面。
- 让相同类别的任务、表单、数据表和危险操作使用一致交互模式。
- 让导航、键盘、焦点、窄窗口和长任务反馈可靠。
- 移除页面内视觉魔数，建立有限且有名称的语义设计令牌。
- 改造可按页面分批验收、可回滚，不需要一次性重写全部 UI。

### 非目标

- 不改搜索策略、筛选条件、排序、缓存策略、下载规则、上传目标、重试次数、队列顺序、清理匹配或删除语义。
- 不修改 Whisper 模型、精度、批次、解码参数和字幕完整性规则。
- 不把所有内部运行参数变成用户可调设置；不因为视觉整理新增配置项。
- 不在视觉改造中同时迁移路由框架、替换状态管理库或重写 Main 领域服务。
- 不通过删除日志、状态字段、确认步骤来追求页面简洁。

## 3. 审计发现与优先级

### P0：先解决安全和高风险操作

1. **页面交互不得绕过现有预览和确认门禁**。本次静态审计没有判定各危险操作的现行确认实现是否充分；实施前对上传、清理、重复删除、批量清空和重置逐项实测。改造不得减少确认信息和授权范围约束。
2. **危险操作结果必须可判断**。页面应展示本次作用范围、成功数、失败数、失败条目和后续可行动作；不允许把部分失败显示为统一成功。
3. **避免重复触发副作用**。单击执行后立即锁定重复入口，直到返回有效结果或确认取消；错误/超时后依据当前业务规则判断是否能安全重试。

### P1：主要交互和可访问性

1. **view/history 多 owner**：`useShellNavigation.js` 与 `useAppShellController.js` 都修改 URL/history；导航和认证回调也能改 `currentView`。统一为一个 view transition owner，区分 `push`、`replace`、`popstate` 和无需留历史的内部恢复。非法 view 回到首页并用 `replaceState` 修正地址。
2. **折叠导航状态表达错误**：折叠分组使用 `<details>`，但 `aria-expanded` 绑定当前组是否活跃，而不是 disclosure 的实际打开状态。按真实展开状态修正。移动抽屉需实现打开后焦点进入、Tab 限制在抽屉中、Escape 关闭、关闭后焦点回到触发器；背景内容在抽屉开启时不可继续操作。
3. **导航语义**：保留 `<nav>`、按钮和 `aria-current="page"` 语义。图标/折叠态按钮必须有可访问名称；当前选中、展开、禁用状态同时有语义和可见表现。
4. **页面层级**：每个页面使用一个明确的 `h1`，标题下先给页面目的/当前状态，再给主要动作，然后再给次要设置和结果。避免同页多个视觉主按钮竞争。
5. **表单状态**：每个字段有可见 label、单位/格式说明、范围、默认值的含义；错误贴近字段；保存区分未更改、待保存、保存中、保存成功和失败。敏感值默认遮蔽，显示/隐藏控件有名称。
6. **异步状态**：加载、空结果、陈旧结果、无权限/未连接、失败和部分成功必须区分。`aria-live` 仅放在实际会更新且需要播报的状态上，避免整个大面板更新导致重复播报。
7. **控件状态**：执行中的按钮需禁用同一副作用入口并说明进行中；支持取消的任务要明确取消影响，不支持取消时不得伪装提供取消。
8. **窗口适配**：目标是桌面应用的窄窗口兼容，而非手机 Web。侧栏抽屉、固定按钮、表格、弹窗、表单应在 1024px、768px、640px 宽内容视口及高缩放/系统字体时保持可操作；记录实际最小支持 Electron 窗口尺寸。

### P2：信息密度、性能和维护成本

1. 页面重复布局、按钮、状态标签、表单行和对话框需共享基础组件/令牌，页面业务仍归各页面所有。
2. 大页面按边界拆分，不以行数作为唯一目标：可观察展示组件、纯转换函数、局部表单、操作控制器分别具备清晰输入输出和测试点。
3. `app-view-registry.js` 已对多数低频页面使用异步组件；`WhisperTool`、`TranslationAutomation` 和 `AsmrDownloader` 仍是静态导入。先保存当前首屏 chunk/页面切换耗时，再决定进一步异步化，不把“使用 lazy import”当性能验收。
4. 列表在数据量达到 50 项以上时测量滚动/渲染；只有测量证实有成本才引入虚拟列表，并保持键盘选择和批量操作可用。
5. 视图 composable 的名字需表达职责；先拆清控制器/状态模型，再分批调整命名，避免机械重命名导致 import/测试大面积噪声。

## 4. 全局导航和应用外壳

### 4.1 导航信息架构

- 保持 4 个一级业务分组：任务处理、数据工具、Telegram、系统；不因 UI 改造改变功能归属。
- 首页为独立入口；最近访问保持可选快捷区且不替代完整导航。
- 侧栏展开态显示分组标题和页面名；折叠态 tooltip 必须可通过键盘焦点触发，子菜单不可只靠 hover 使用。
- 当前页面的父分组保持可发现；折叠/展开不会意外改变当前 view。
- `clean` 父项的语义是展开清理子页面；不得让它落入未注册 view 并显示空白或错误 fallback。

### 4.2 view 与 history

- 只有导航层可提交页面切换；页面/认证流程调用该入口，不直接写 URL 和 `currentView`。
- `?view=` 接受注册表中的页面 key；非法 key 回退首页并替换地址。
- 点击导航使用 `pushState`；应用启动规范化地址使用 `replaceState`；浏览器/Electron history 的 `popstate` 只恢复当前 view，不再 push 新条目。
- 刷新后恢复页面 key；临时页面内表单数据是否保留另行定义，不能承诺未持久化状态会恢复。
- 最近访问和导航组偏好只保存在本地 UI 状态；未知 key/分组可被忽略，不做配置数据迁移。

### 4.3 窄窗口和焦点

- 侧栏抽屉打开：焦点移动到关闭控件或首个导航项，Tab 不离开抽屉，Escape 关闭；关闭后回到菜单触发器。
- 遮罩点击可关闭；点击导航项后关闭抽屉，但 `clean` 父项展开子菜单时不关闭。
- 桌面折叠导航无 hover-only 的关键入口；键盘和触屏可完成相同操作。
- 跳过导航链接聚焦主要内容。页面切换后将焦点移动到页面标题容器（`tabindex="-1"`）或以等价方式提供可感知的页面切换反馈。
- 调整窗口时不得裁切主要 CTA；内容区只允许一个主要纵向滚动容器，必要的表格横向滚动要局限在表格容器。

## 5. 设计系统规范

### 5.1 品牌方向

采用“安静的资料室 / 桌面操作台”：温和纸白背景、深墨色文字、石绿/深青作为主要操作色、珊瑚/赤陶只用于警告与重要状态。页面应像高密度专业工具，不做泛 SaaS 仪表盘，也不把每个区域做成悬浮卡片。

### 5.1.1 当前实现基线

当前代码已经存在一部分外观状态，但它不是完整的多主题系统：

- `config.system.theme` 当前支持 `auto`、`light`、`dark` 三种值。
- `config.system.accentColor` 当前支持用户选择强调色。
- `useWindowShellState.js` 通过 `data-app-theme`、CSS 变量和窗口外观状态应用颜色、透明度和模糊。
- 设置页当前还暴露窗口边框、透明度、毛玻璃和毛玻璃强度；这些属于窗口效果，不应和主题语义混在一个“主题色”选项中。窗口透明度会映射到 Electron 原生窗口 opacity，可能降低整个窗口内容可读性；Renderer 也在标题栏和页面区域使用 backdrop blur。
- 当前暗色文字覆盖规则会把 `.app-shell` 及其子节点的文字统一设为白色；实施多主题时必须改为语义 token 映射，不能继续依赖全局强制覆盖，否则会破坏错误色、禁用色、表格层级和输入提示的对比度。
- 当前配置契约没有字体家族、文字缩放或数据密度字段。文字自定义需要先完成配置 owner、保存位置、迁移和回滚设计，不能只在 Renderer 写入本地临时状态后宣称已持久化。

### 5.2 多主题模式

主题不是每个页面单独换一套颜色，而是“主题预设 → 语义令牌 → 组件状态”的三层模型。页面只能使用语义令牌，不能直接写主题色值。

#### 主题预设

v1 方案预留以下预设，最终名称和色值在视觉评审后确定：

| 预设 | 用途 | 必须保证 |
| --- | --- | --- |
| 暖纸工作台 | 默认品牌主题，适合长时间阅读和数据整理 | 纸白/暖灰层次、深色正文和石绿主操作 |
| 森林 | 偏绿的低刺激配色 | 成功色仍与主色区分，不把状态色混为主题装饰 |
| 海湾 | 偏蓝/青的冷静配色 | 信息色不与主操作和链接色混淆 |
| 高对比 | 高缩放、投影和对比敏感场景 | 强化文字、焦点环、边界和选中态；减少透明和背景装饰 |
| 用户强调色 | 在选定主题上使用用户选择的强调色 | 通过可读性校验，不修改危险/成功/错误语义色 |

每个主题预设都提供亮色/深色配对；亮暗模式仍使用现有 `system.theme` 的跟随系统/浅色/暗色选择。最终主题名称、颜色和组合在视觉评审后确定。

主题选择必须显示当前预览、应用范围和恢复默认入口。主题切换只改变展示，不触发业务请求、任务重启、配置迁移或页面刷新。

#### 主题应用模型

建议由一个 Renderer 主题控制器统一负责以下流程：

1. 读取已保存主题偏好并校验值；未知值回退到 `auto`，不让页面进入半套主题。
2. 解析 `system.theme` 的 `auto`/`light`/`dark` 外观模式和 `system.themePreset` 主题配色，得到当前实际亮/暗配对及配色。
3. 将主题配色、亮暗模式和高对比状态映射到语义 token，再写入根元素属性和 CSS 变量；页面组件不直接读取配置值决定颜色。
4. 主题切换只更新展示状态；保存失败时恢复上一个已保存值，并在设置页显示失败原因。
5. 系统主题变化只影响 `auto`，手动选择的主题不被系统事件覆盖。

主题状态至少分成：`modePreference`（跟随/亮/暗）、`palettePreference`（配色预设）、`resolved`（当前实际配对）、`preview`（尚未保存的临时预览）、`persisted`（已保存值）。预览和持久化值不得混用。

#### 主题令牌

主题令牌至少覆盖：`canvas`、`surface`、`surface-raised`、`text-primary`、`text-secondary`、`text-disabled`、`border`、`divider`、`focus-ring`、`action-primary`、`action-secondary`、`action-danger`、`status-success`、`status-info`、`status-warning`、`status-error`、`overlay`、`shadow`。

- 每套主题都要提供文字、图标、控件边界、禁用、悬停、按下、选中、焦点和错误配对。
- 用户自定义强调色必须经过亮度/对比度校验；不合格时拒绝保存并说明原因，而不是自动生成难以理解的替代色。
- 高对比预设禁止依赖渐变、玻璃模糊、低透明边框和仅靠阴影表达层级。
- 主题预览应在设置页内完成，且至少覆盖按钮、输入框、表格、状态条、弹窗和危险确认框。

### 5.3 用户可选文字显示

“文字支持自己选择”按 v1 方案解释为：用户可以选择界面字体、文字缩放和数据密度；不允许任意输入会导致页面不可读的 CSS 值。

文字设置与主题设置分开保存、分开恢复默认，但在同一设置页提供联动预览。主题切换不应覆盖用户的字体和字号选择，用户更换字体也不应改变主题色和状态语义。

#### 用户选项

| 选项 | 建议值 | 行为 |
| --- | --- | --- |
| 界面字体 | 系统默认、内置推荐字体，或用户设备已安装的字体名称 | 只影响 Renderer 展示，不修改字幕、上传内容、文件名或外部消息 |
| 文字大小 | 小、标准、大、特大，或受限比例滑杆 | 以标准值为基准整体缩放正文、字段、表格和辅助说明；标题单独限制最大值 |
| 数据密度 | 舒适、标准、紧凑 | 调整表格行高、控件间距和内边距，不通过缩小正文隐藏内容 |
| 编号/日志字体 | 跟随界面、等宽 | 只影响 RJ/VJ/BJ 编号、路径、时间、日志和代码区域 |
| 字体平滑/系统渲染 | 跟随系统 | 不在应用内提供会造成跨平台不可预测的低级渲染开关 |

建议的字体选择按“用途”区分，避免正文和数据字体互相影响：

| 字体角色 | 默认 | 可选范围 | 适用区域 |
| --- | --- | --- | --- |
| UI 正文 | Windows 中文系统字体栈 | 推荐中文无衬线字体，或用户已安装字体 | 页面正文、按钮、字段、状态 |
| 标题 | 跟随 UI 正文 | 推荐标题字体，或跟随正文 | 页面标题和分组标题 |
| 数据/日志 | 系统等宽字体栈 | 推荐等宽字体，或用户已安装字体 | RJ/VJ/BJ、路径、时间、日志、错误码 |

允许用户从推荐列表选择，也允许填写本机已安装字体的名称；不允许上传字体文件或把任意 CSS 片段作为配置。自定义字体名称作为普通文本存储，限制长度并拒绝换行/控制字符，Renderer 以安全的 CSS 字符串方式应用。应用提供预览；若设备没有该字体，按系统 fallback 展示并提示用户检查字体名称/安装状态，不得导致整页字体失效。

#### 文字显示约束

- 字体选择必须有即时预览、恢复默认和“当前应用范围”说明；设置保存失败时保留原值。
- 字体不可用、被系统移除或加载失败时回退到安全字体栈，并在设置页显示回退提示。
- 文字缩放使用语义级别而不是对整个窗口做 CSS `transform: scale()`，避免焦点、弹窗和点击坐标错位。
- 200% 缩放下允许内容变高，但不得隐藏主按钮、错误信息、字段 label、弹窗确认和表格操作列。
- 用户选择的字体不得影响导出文件、字幕内容、Telegram 消息或业务排序。
- 颜色、字号和字体变化都不能替代可读的状态文字；成功/失败/警告仍需文本或图标说明。

#### 配置契约建议（待单独批准）

如果要把主题预设、字体和字号作为跨重启的用户偏好，建议复用现有 `system.theme` 明暗模式字段，在 `system` 用户偏好下只增加受控配色/文字字段，而不是创建第二个 UI 配置文件：

```text
system.themePreset: warm-studio | forest | sea-glass | high-contrast
system.fontFamily: string (empty means follow system)
system.dataFontFamily: string (empty means use default data font)
system.fontScale: small | standard | large | xlarge
system.density: comfortable | standard | compact
```

这只是待批准的契约草案，不代表当前配置已经支持这些字段。沿用现有 `system.theme` 的 `auto`/`light`/`dark` 值，不创建第二个明暗模式字段；保留现有 `system.accentColor` 并确保主题切换不覆盖用户强调色。实施前必须补充：默认值、模板生成、字体字符串校验/安全应用、旧版本读取策略、非法值回退、保存失败回滚、设置页显示和测试。

兼容要求：已有用户的 `system.theme` 和 `system.accentColor` 原值必须保留。新配色字段只增加默认值，不得把旧浅色/暗色映射成另一主题；降级/回滚时忽略未知配色/文字字段但保留数据。是否需要提升 configVersion，由实施时对当前迁移器和版本策略核对后决定。

#### 设置页交互

设置页面新增的视觉选项应按“实时预览 → 应用 → 恢复默认”组织；若保存配置需要重启，必须明确显示“立即生效”还是“重启后生效”。预览状态和已保存状态分开，不允许用户以为尚未保存的主题已永久写入。

建议的设置页分组顺序：

1. **明暗模式**：沿用当前跟随系统、浅色、暗色选择；显示当前解析到的明暗配对。
2. **配色主题**：暖纸工作台、森林、海湾、高对比等主题预设；显示当前预览。
3. **强调色**：沿用当前自定义强调色；切换主题不覆盖用户值，显示对比度检查结果。
4. **文字显示**：字体角色、文字大小、数据密度、编号/日志字体；提供示例文本预览。
5. **窗口效果（高级）**：边框模式；默认不展示需要性能权衡的旧模糊渲染模式。
6. **性能选项**：默认关闭模糊和窗口级透明；高性能模式作为默认。若保留“柔和效果”，必须是局部、低强度、可关闭的装饰，且不能作用于连续滚动的大内容区。
7. **操作**：应用、恢复配色默认、恢复文字默认、恢复全部外观默认；每个动作标明作用范围。

### 5.3.1 窗口效果与性能方案

原“毛玻璃/透明窗口”方向改为性能优先方案：主题表面使用不透明颜色，层级通过明度、细边框、留白和静态阴影表达。清晰可读、滚动稳定优先于背景透视或玻璃质感。

| 效果 | v1 默认 | 方案 |
| --- | --- | --- |
| Electron 窗口整体 opacity | `1.0` | 不对整个窗口降透明；避免文字、图标、弹窗和焦点一起褪色 |
| Main 内容、侧栏、标题栏、卡片 backdrop blur | 关闭 | 使用不透明主题表面；不对滚动内容持续执行背景采样/重绘 |
| GPU/系统 blur 渲染模式 | 不作为普通主题选项 | 从基础外观设置中移除选择；避免用户误以为能稳定提升性能或跨设备一致 |
| 阴影 | 静态、少量、低扩散 | 只用于浮层/弹窗，不对大面积容器叠多层阴影 |
| 渐变与装饰背景 | 静态、低对比、少量 | 不使用持续动画或大面积透明渐层作为主内容背景 |
| 页面切换动画 | 短暂 opacity | 避免大面积模糊、缩放和连续位移动画 |

如果产品仍需保留视觉特效，只保留“关闭 / 轻量”两档；轻量档仅允许静态强调色、细边框和单层阴影，不再提供 GPU/system 两类模糊模式。性能模式直接关闭所有非必要 blur、透明和动画，主题的配色选择与性能模式相互独立。

#### 设置/配置迁移建议

- 默认设置新安装的窗口 opacity 为不透明，模糊默认关闭；新主题全部采用不透明 surface。
- 对已经保存透明度或启用模糊的用户，需决定“首启一次性迁移到性能默认”还是“保留旧偏好但提供性能提醒”。推荐对新用户采用性能默认；已有用户首次升级保留其偏好，在设置中提示可一键启用性能模式，避免静默改变熟悉的外观。
- 若产品决定强制性能优先，必须明确批准一次性迁移、旧字段处置、降级行为和回滚方式；不允许 Renderer 与 Main 分别套用不同默认。
- 旧 `blurEnabled`、`blurIntensity`、`blurRenderMode`、`windowOpacity` 字段的删除或重解释属于配置契约变化，需要单独批准、迁移测试和模板更新；本 UI 方案不直接改这些字段。
- 设置页将窗口效果单独列在高级区；主视觉设置先展示明暗模式、主题配色、文字选项和性能模式，避免把 blur 强度误当主题质量控制。

#### 性能验收

- 关闭特效与启用轻量效果两种状态下，在同一台目标设备比较滚动列表、日志追加、页面切换和窗口拖动。
- 记录 Renderer CPU/GPU 使用、掉帧/滚动卡顿主观检查及持续运行温度/风扇观察；短时截图不作为性能证据。
- 长列表、日志、状态流更新期间不得因背景 blur 产生持续重绘；窗口失焦不应触发昂贵的特效状态切换。
- 低端/集显设备默认不启用 GPU blur；不以“GPU 加速”名称推断用户设备一定更快。

### 5.4 颜色语义

实现前在全局 tokens 文件中定义并同时审查亮/暗主题的语义配对，不直接照抄现有建议色值：

| Token 类别 | 用途 |
| --- | --- |
| `canvas` / `surface` / `surface-raised` | 页面底、内容区、对话框/菜单 |
| `text-primary` / `text-secondary` / `text-disabled` | 标题、说明、禁用内容 |
| `border` / `divider` / `focus-ring` | 分区和键盘焦点 |
| `action-primary` / `action-secondary` / `action-danger` | 主要、次要、破坏性动作 |
| `status-success` / `status-info` / `status-warning` / `status-error` | 状态文字、图标和背景配对 |

普通正文对比度达到 WCAG AA 4.5:1；大号文字和非文本控件边界至少 3:1。状态不能只靠颜色区分。

### 5.5 字体与尺寸层级

- 保持 Windows 中文环境可用的系统字体 fallback；如引入字体文件，先审核授权、包体积、加载闪动和离线可用性。
- 用户字体选择按已验证推荐字体或用户输入的本机字体名生效；必须有可靠回退链和预览。
- 建立标题、正文、字段 label、表格、辅助说明、代码/编号的有限字号级别；正文不小于 14px，密集数据不得靠缩到 11-12px 获得容量。
- 编号、时间、金额和计数优先使用等宽数字或 `font-variant-numeric: tabular-nums`，减少刷新抖动。
- 标签、编号、错误文本允许换行或明确省略并提供完整查看；禁止破坏自然中文换行。

### 5.6 间距、圆角、边框和动效

- 使用 4px 基数、8px 常用间隔的有限间距阶梯；页面只引用 token，不添加孤立的布局魔数。
- 以分区间距、细分隔线和标题层级建立信息组；卡片仅用于独立任务面板、浮层和危险结果，不要把每一个小设置包成一张卡。
- 统一小/中/大圆角、控件高度和边框粗细；触屏或高密度鼠标操作区域不小于约 40px，高频图标按钮至少 40×40px。
- 页面切换采用轻淡入；耗时状态变化使用短暂且语义明确的反馈；不做持续漂移、装饰性呼吸或会影响扫描的数据动效。
- `prefers-reduced-motion: reduce` 下删除非必要位移/缩放，仅保留必要的状态切换。

### 5.7 图标、卡片和数据组件

- 使用项目现有 SVG 图标体系中的一个一致风格；不得以 emoji 或随意 Unicode 符号替代导航/系统图标。
- 有可见文字的装饰图标使用 `aria-hidden="true"`；图标按钮必须有名称；图标不能独立承载成功/失败意义。
- 表格固定主识别列和操作列；其余列按信息优先级调整/折叠，不让操作列横向滚出视野。
- 可批量选择的表格必须标注当前选择数量，提供全选范围（当前页/全部结果）和清空选择的明确定义。

## 6. 逐页面改造规格

下列每页均要交付：新旧截图、交互检查、状态截图、保持的业务规则、触及组件清单。页面内容和业务规则必须先从当前组件/Composable 核实。

### 6.1 首页 `HomePanel.vue`

- **目标**：呈现能执行的工作台，而不是宣传页；优先提供常用入口、最近任务/最近结果和账户/外部依赖状态。
- **布局**：顶部标题与简短说明；第一行放高频任务快捷入口；其余区域按“正在运行/最近完成/需要处理”分组。
- **交互**：每个快捷入口进入真实 view；没有可用的实时状态时明确写“未连接/未加载”，不造假数字或 mock 数据。
- **状态**：首次载入、无历史、接口失败和存在待处理事项分别有页面状态。
- **验收**：键盘能依序到达快捷入口；刷新不产生任务副作用；空账户显示引导而不是空白卡。

### 6.2 上传工具 `UploadToolPageContentCore.vue`

- **目标**：将上传分成文件来源/扫描、待上传清单、上传设置、执行控制、结果日志五个区域。
- **交互**：区分压缩包扫描与手动文件两种入口；扫描结果可复核后再开始；执行时显示每项状态和当前文件，取消入口只在业务支持时出现。
- **高风险**：开始上传前展示文件数、目标频道/目标配置和已有确认记录提示；confirmed 项不可被重新触发，uncertain 项进入人工复核。
- **状态**：未扫描、扫描中、无匹配、可上传、上传中、已取消、全部成功、部分失败、结果不确定。
- **验收**：连续点击不能并发重复上传；窗口关闭/重启恢复说明与现行恢复逻辑一致；日志支持滚动到底但新日志不强制夺焦点。

### 6.3 Whisper `WhisperTool.vue` / `WhisperProgress.vue`

- **目标**：把可执行文件路径、输入/输出路径、字幕格式作为任务准备区；任务状态和结果作为独立区域。
- **交互**：路径选择提供当前值和无效/不存在提示；提交前展示输入文件/目录与输出目标；运行中显示阶段、耗时、最后活动和可用操作。
- **硬边界**：模型、精度、batch、解码不因 UI 整理改变；不得改写生成完成判定和字幕完整性检查。
- **状态**：依赖未配置、预检失败、排队、转写、打包、验证失败、已完成、取消、崩溃中断、可恢复。
- **验收**：失败结果明确区分缺依赖、转写失败、字幕验证失败和打包失败；历史任务恢复动作严格使用现有恢复状态机。

### 6.4 自动翻译队列 `TranslationAutomation.vue`

- **目标**：一屏看到运行状态、当前作品、阶段、队列分布、策略配置、最近一轮结果和日志；减少英语装饰标题与内容竞争。
- **交互**：主动作“立即运行一轮”在运行时锁定；失败可重试时显示错误原因和目标作品；设置编辑与保存状态分离。
- **信息层级**：将运行策略分成基础设置和高级策略；高级区折叠默认状态由产品确认，不能在 UI 内私自调整后台默认值。
- **状态**：已关闭、等待调度、运行中、等待外部进度、可重试失败、人工复核、成功完成；最近一轮明确显示各阶段数量。
- **硬边界**：自动翻译仅在上传成功且队列清理成功后完成；不改变时间窗、队列顺序、worker 并发或 retry 策略。
- **验收**：很长的运行日志不造成页面卡顿；区域只读更新不会频繁触发屏幕阅读器重复播报。

### 6.5 音声下载 `AsmrDownloader.vue`

- **目标**：明显分开任务输入、参数/输出、计划预览、提交结果、人工复核。
- **交互**：批量编号粘贴/文件导入显示解析数量和无效项；RPC/目录设置按需展开；预览列出将自动提交、跳过、需人工处理的计数。
- **状态**：解析中、无有效编号、预检失败、已生成预览、提交中、部分推送失败、重复任务、人工复核。
- **硬边界**：保留指纹、格式优先级、视频兜底、自动任务上限、Aria2 GID 和测试模式含义。
- **验收**：用户能区分“下载计划生成”与“已写入 Aria2”；错误项可复制/查看原始错误，不能把提交失败显示为下载失败或成功。

### 6.6 最近活动 `RecentActivityPageContentCore.vue`

- **目标**：突出历史筛选、目录选择、扫描、清单选择、下载动作和逐项下载结果。
- **交互**：默认保留上一次筛选只要当前实现已持久化；批量选择显示数量和适用范围；下载期间显示进度和可用取消。
- **状态**：无记录、读取历史失败、筛选无匹配、正在扫描、准备下载、下载中、部分失败。
- **验收**：目录和筛选变更后清楚提示是否需要重新扫描；取消行为不丢失已完成项状态。

### 6.7 本地清理 `LocalCleaner.vue`

- **目标**：采用“选择来源 → 扫描/载入 → 预览候选 → 选择 → 执行 → 结果”的可见步骤。
- **交互**：显示扫描路径、候选数、已选数、文件存在性；“全选”须写清作用于当前页还是全部结果；删除主按钮必须是危险样式。
- **风险保护**：执行前再次显示根目录、目标数量和匹配规则摘要；若当前 API 支持 preview token/二次授权，UI 必须完整呈现。
- **状态**：路径未选、扫描中、零候选、可删除、执行中、逐项失败、完成。
- **验收**：错误路径或 0 项时不能提交；扫描结果变更后旧选择失效或明确保留策略。

### 6.8 云端清理 `CloudCleaner.vue`

- **目标**：把数据源（云端/最近上传）、标签筛选、作品列表、选择统计、删除预览和结果分层。
- **交互**：搜索与标签组合条件需可见；OR/AND 选择附简短解释；刷新/拉取期间锁定冲突动作；选择总数和影响数量分开显示。
- **风险保护**：执行前列出目标作品/RJ 列表、来源和无法删除项目；刷新数据后对旧选择做清空或重新验证。
- **状态**：未连接、载入中、空结果、筛选无匹配、可操作、部分失败。
- **验收**：任何删除使用现有预览/确认合同；云端刷新失败不清空最后成功数据而不提示。

### 6.9 高级搜索 `AdvancedSearch.vue` 与 `SearchPreview.vue`

- **目标**：按发现条件分组筛选条件；摘要当前生效条件并提供清晰的执行/重置动作。
- **交互**：Reset 说明重置范围；查询中避免重复请求；预览区显示查询条件摘要、结果数、来源和分页/截断信息。
- **状态**：默认条件、条件无效、查询中、空结果、部分结果、请求失败。
- **验收**：编辑条件不隐式执行副作用；复查组件的嵌套选择器（标签、年龄、时长、价格、评级）键盘操作和删除 chip 的名称。

### 6.10 RJ 过滤 `RjFilter.vue`

- **目标**：按来源、日期规则、既有列表、执行选项、筛选结果、快照比较分组。
- **交互**：明确当前输入来源和将执行的条件；进度显示已处理数/阶段；快照载入与当前结果差异比较使用独立 CTA。
- **状态**：URL 无效、读取来源中、无结果、正在过滤、结果分页、差异比较、失败可重试。
- **硬边界**：RJ/VJ/BJ 规范化、日期含义、黑名单和上游协议不变。
- **验收**：每页计数、总数、当前快照和已加载快照不混淆；日志清理不会删除持久快照。

### 6.11 中文列表 `ChineseListPageContentCore.vue`

- **目标**：明确“数据源/导入”“当前合并列表”“差异/冲突”“保存目标”四部分。
- **交互**：TXT 拖拽区同时提供可点击文件选择；拖入和文件选择均给出文件名、RJ 数、去重数、无效数；清空全部数据使用危险确认。
- **状态**：未载入、导入中、解析错误、空列表、合并有变化、未保存、已保存。
- **验收**：拖拽不是唯一输入方式；切换路径或多来源时说明是否会覆盖、合并或追加，沿用现有真实语义。

### 6.12 工具箱 `Tools.vue`

- **目标**：将提取文件名、数据清洗、清理最近上传字幕、字幕格式转换、字幕打包组织成一致的独立工具区。
- **交互**：每个工具使用固定模式：用途一句话、输入、选项、输出预览/路径、主动作、结果。长页面使用锚点目录或折叠导航，但各工具不能互相覆盖配置。
- **风险保护**：覆盖已有文件前使用现有覆盖确认；输出路径和匹配数量在执行前可见。
- **验收**：每项工具独立 loading/error；某个工具失败不清空其他工具输入；目录选择按钮键盘可达。

### 6.13 Telegram Bot `TgSearchBot.vue`

- **目标**：把 Bot 连接状态、控制动作、索引任务、搜索和作品信息查询拆成明确区域。
- **交互**：状态区显示运行/停止/错误、上次更新时间；Start/Stop 互斥且反馈任务完成；搜索表单支持 Enter 与按钮一致的 loading/错误语义。
- **状态**：未配置、未运行、连接中、运行中、同步中、状态不可用、搜索无结果、搜索失败。
- **验收**：危险/权限错误使用明确结果；Bot 状态刷新与信息缓存刷新不得复用错误提示通道。

### 6.14 TG 信息缓存 `TgInfoCache.vue`

- **目标**：首屏显示命中/陈旧/失败/总量/最近刷新；导入文件、构建缓存和调度器控制放入任务操作区域。
- **交互**：构建输入来源、代码数量、估计操作范围先确认；执行中禁用重复构建和互斥动作。
- **状态**：缓存为空、已有缓存、陈旧、构建中、退避等待、构建部分失败。
- **验收**：保留陈旧命中但展示其新鲜度；失败不误报缓存已刷新；危险的缓存重置需确认影响路径/记录范围。

### 6.15 TG 异常恢复 `TgInfoErrorRecover.vue`

- **目标**：拆成连接/频道来源、错误分类、下载/输出选项、安全模式、恢复预览和执行摘要。
- **交互**：数值参数显示单位和边界；高级参数折叠但保留当前值；开始前展示扫描范围、预计处理量以及安全模式影响。
- **状态**：配置缺失、连接测试、预检、执行中、跳过项、部分成功、失败。
- **硬边界**：只改变展示、解释和校验提示；不能扩大目标频道、授权、下载范围或改变安全模式默认。
- **验收**：用默认值、最小/最大边界和非法值分别验证；执行结果可追踪每类跳过/失败原因。

### 6.16 RJ 重复检测 `RjDuplicateDetector.vue`

- **目标**：提供扫描配置、扫描进度、分组结果、保留/删除预览、审计导出五个层次。
- **交互**：分组标题显示重复组、候选删除数、默认保留项；选择统计与建议删除数量分开；执行前展示将保留和将删除的条目。
- **风险保护**：默认保留最新规则不得藏在单一图标或摘要；每次执行引用预览并逐项写出结果。
- **状态**：扫描中、无重复、可预览、预览过期/需刷新、删除中、部分失败、审计导出完成/失败。
- **硬边界**：保留最新、预览门禁、删除目标和审计规则不变。
- **验收**：空选择、旧预览、重复点击、单项失败、审计导出失败各有独立结果。

### 6.17 设置 `SettingsPageContentCore.vue`

- **目标**：按用户任务分区：账户状态、Telegram、ASMR、目录/存储、系统外观、日志/高级。每区显示是否完成配置，而不是一页平铺几十个字段。
- **交互**：必需/可选字段标清；账号登录状态和凭据编辑分开；测试连接/保存/登录不混成一个按钮。保存反馈说明何时生效（立即、需重启、下次任务）。
- **配置精简**：默认展示用户可理解且会主动决策的偏好；内部调度参数置入高级区域并解释；未完成读写影响盘点前不删任何字段、不改默认值。
- **风险保护**：Token、Hash、密码默认遮蔽；路径选择控件提供清空/还原默认但须明确副作用；配置目录迁移提示旧配置位置和保存目标。
- **状态**：配置加载、未保存更改、保存中、保存失败、保存成功、认证等待验证码/密码/成功/失败。
- **验收**：折叠区标题宣布展开状态；切换主题不丢失未保存字段；认证弹窗初始焦点、焦点陷阱、Escape 与错误关联正确。

## 7. 共享页面模板与组件职责

实施 Agent 可复用组件，但必须满足职责单一，不创建全能页面框架。

- `PageHeader`：唯一主标题、用途说明、最多一个主 CTA 和必要的次动作。
- `StatusBanner`：状态类别、标题、说明、可选恢复 CTA；错误和警告不只依赖颜色。
- `TaskStagePanel`：阶段、进度、最后活动、当前对象、支持的取消/重试/恢复动作。
- `FilterToolbar`：当前生效条件、筛选重置和结果数；不同页面的业务条件仍由页面拥有。
- `SelectionSummary`：选中数、可操作数、范围和批量动作入口。
- `DangerPreviewDialog`：影响对象、数量、授权/路径、不可逆提醒、确认短语是否需要由风险评审决定。
- `InlineField`：可见 label、说明、输入、单位、错误，不把 label 只放 placeholder。
- `EmptyState`：解释为何为空、如何开始；不提供会绕过业务前置条件的虚假 CTA。
- `OperationLog`：分级、时间、任务 id、复制能力和增长限制；不得吞掉可诊断错误。

共享组件只统一呈现和语义，不负责偷偷改变频道名、任务调度、默认参数或业务策略。

## 10. 验收清单

### 一致性与可访问性

- [ ] 17 个页面均有唯一明确的页面标题和可理解的主要动作。
- [ ] 所有交互控件可用键盘操作；焦点可见、顺序符合视觉阅读顺序。
- [ ] 导航分组 `aria-expanded` 与实际状态一致；当前页 `aria-current` 唯一正确。
- [ ] 图标按钮均有可访问名称；装饰图标不重复播报。
- [ ] 表单有可见 label、错误信息和保存状态；敏感值默认隐藏。
- [ ] 加载、空、陈旧、失败、部分成功均可通过文字/语义识别。
- [ ] 浮层能关闭、焦点不丢失、不被遮挡；Escape 仅在安全语义下关闭。
- [ ] `prefers-reduced-motion` 和 200% 窗口缩放不破坏主要操作。
- [ ] 默认窗口 opacity 为 1，主内容/侧栏/标题栏/卡片不依赖 backdrop blur；关闭特效时页面层级仍完整。
- [ ] 轻量效果只使用静态颜色、边框和单层阴影；滚动内容中没有大面积 blur。
- [ ] 关闭特效与轻量效果都完成同设备的滚动、日志追加、窗口拖动和页面切换性能对比。

### 业务安全与流程

- [ ] 上传 confirmed/uncertain 语义、删除预览、授权范围和部分失败行为不变。
- [ ] Whisper 参数及字幕完成条件不变。
- [ ] 搜索顺序、过滤规则、缓存新鲜度和来源优先级不变。
- [ ] 下载身份、格式优先级、视频兜底、上限和人工复核不变。
- [ ] 自动翻译完成门槛、队列顺序、调度窗口和并发不变。
- [ ] 页面更改没有新增用户配置字段，没有悄悄更改现有配置默认值。

### 交付质量

- [ ] 页面首次进入反馈及时；切换页无白屏、重复请求或未处理异常。
- [ ] 窄窗口下主操作不被遮挡，表格不压坏列内容，弹窗可滚动和确认。
- [ ] 长列表经测量后才采用虚拟化，选择和键盘操作仍正确。
- [ ] 亮/暗主题文本对比达到 AA；状态文字不依赖颜色。
- [ ] 每个配色主题均有亮色和深色呈现；高对比主题的边界、正文和焦点环可辨识。
- [ ] `auto` 模式跟随系统主题；用户选择主题/字体/字号可保存、重启后恢复，保存失败可回滚。
- [ ] 用户输入字体名在未安装和错误名称时安全回退；不影响导出文件和业务文本。
- [ ] 字体大小和数据密度独立可调；200% 缩放时不丢失主动作、错误文本和确认按钮。
- [ ] 主题、字体或性能模式切换不发起业务请求、不重启长任务、不改变业务结果。
- [ ] 测试、构建、协议、文档检查结果与 GUI/在线/安装包证据分开记录。

## 11. 尚待设计批准的决策

- 是否采用深青/石绿与陶土色为最终品牌色，以及最终亮暗色值。
- 是否引入本地字体文件或只用系统字体 fallback。
- 最小支持 Electron 窗口宽高、建议默认窗口尺寸和侧栏断点。
- 首页应显示哪些真实摘要数据；若需新增查询，应另立数据/API 任务而非伪造 UI 数据。
- 高级配置哪些字段可见/折叠；须先做配置读写影响盘点，避免静默删项。
- 每个危险操作的确认强度、是否要求重新输入编号，以及现有 Main 端授权合同能否支持。

本方案已进入 `in-progress`。本轮仅执行已授权的 Renderer 范围；多主题持久化、用户字体/字号配置、危险操作确认强度、最小 Electron 窗口尺寸等仍保持待批准，不在本轮擅自扩大。
